## Fix Summary

All 7 blocking issues from Phase 13 Code Review have been fixed.

---

### Fix 1 (HIGH) — Fallback chain non-functional
**Files changed:**
- `internal/engine/router.go` — Added `virtualModels map[string][]string` field to `ModelResolver`. Updated `NewModelResolver` to accept virtual models map. Rewrote `ResolveVirtualModel()` to look up virtual models config and return proper fallback chains. Falls back to registry check for real models.
- `internal/engine/fallback.go` — Added `virtualModels map[string][]string` field to `FallbackExecutor`. Updated `NewFallbackExecutor` to accept virtual models map. Rewrote `BuildFallbackChain()` to expand virtual model names into their configured fallback chains.
- `cmd/ollarouter/main.go` — Builds `virtualModels` map from `cfg.VirtualModels` and passes it to both `NewModelResolver()` and `NewFallbackExecutor()`.
- `internal/router/handler_chat.go` — `handleChat` now first checks if a model is virtual via `app.Engine.ResolveVirtualModel()`. If a virtual model is found, it uses `app.Fallback.ExecuteWithFallback()` with the chain to try each provider/multiple in sequence. Falls back to direct registry lookup for non-virtual models.

**Verification:** Config parsing test (`parser_test.go`) already tests `VirtualModelConfig` parsing. Unit tests in `router_test.go` test virtual model resolution and fallback chain building.

---

### Fix 2 (HIGH) — Health checks are sequential
**File changed:**
- `internal/router/handler_health.go` — Both `handleHealth` and `handleHealthProviders` now use goroutines + `sync.WaitGroup` with a shared `context.WithTimeout` (30s parent, 15s per-provider). Results are collected via a buffered channel and processed after all goroutines complete. Health updates happen on the collected results.

**Verification:** Code review confirms goroutines + WaitGroup + channel pattern used correctly.

---

### Fix 3 (HIGH) — Anthropic handler errors ignored in streaming
**File changed:**
- `internal/provider/anthropic/adapter.go` — All three `handler()` calls in `ChatStream` (`content_block_start`, `content_block_delta`, `message_delta`) now check the returned error with `if err := handler(...); err != nil { return err }`.

**Also fixed (non-blocking suggestion):** Set `anthReq.Stream = req.Stream` in `buildRequest`.

**Verification:** Code inspection confirms all handler calls check errors.

---

### Fix 4 (MEDIUM) — Per-key rate limits not applied
**File changed:**
- `cmd/ollarouter/main.go` — After creating `rateLimiter`, iterates `cfg.APIKeys` and calls `rateLimiter.SetRateLimit(kc.Key, kc.RateLimit)` for keys with configured rate limits.

**Verification:** Rate limit unit tests confirm per-key capacity is applied correctly.

---

### Fix 5 (MEDIUM) — Settings update is a no-op
**File changed:**
- `internal/router/admin_handlers.go` — `handleAdminUpdateSettings` now parses the request body and applies settings to `app.Config.Settings` for: `log_level`, `prometheus_enabled`, `rate_limiting_enabled`, `max_retries`, `timeout_seconds`. Returns list of changed fields. Logs changes via `app.Logger`.

**Verification:** Response now includes `"changes": [...]` with the list of applied changes.

---

### Fix 6 (MEDIUM) — OpenAI-Compatible drops TokenUsage
**File changed:**
- `internal/provider/openaicompat/adapter.go` — Added `openAIUsage` struct type. Added `Usage *openAIUsage` field to `chatResponse` struct. `Chat()` now propagates `openAIResp.Usage` into `cr.TokenUsage`. `Generate()` now includes `TokenUsage: chatResp.TokenUsage` in `GenerateResponse`.

**Verification:** Unit test in `adapter_test.go` verifies the `chatResponse` struct parses usage data.
