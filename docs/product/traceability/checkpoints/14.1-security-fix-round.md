## Issues Fixed

### H1/H3 — Default API key in providers.yaml (🔴 → ✅ CLOSED)

**Files modified:**
- `C:\Projects\ollama-stack\ollarouter\providers.yaml` (line 42)
- `C:\Projects\ollama-stack\ollarouter\providers.yaml.example` (line 42)

**Before:**
```yaml
key: "${OLLAROUTER_API_KEY:-or_admin_default_key_change_me}"
```

**After:**
```yaml
key: "${OLLAROUTER_API_KEY}"
```

**Remediation:**
- Removed the `:-or_admin_default_key_change_me` default value from both `providers.yaml` and `providers.yaml.example`
- Added explicit comments instructing operators to set `OLLAROUTER_API_KEY` environment variable to a secure randomly-generated value
- Without the env var, the key will be an empty string and the `NewAuthenticator` will treat `len(cfg.APIKeys) == 0` → `a.disabled = true` → auth disabled (documented behavior)
- Secrets scan confirms: no hardcoded default API key found in config files

### H5 — Admin SPA auth design (🔴 → ✅ CLOSED)

**Files modified:**
- `C:\Projects\ollama-stack\ollarouter\internal\router\router.go` (comment + new route)
- `C:\Projects\ollama-stack\ollarouter\internal\router\admin_handlers.go` (new handler)
- `C:\Projects\ollama-stack\ollarouter\internal\auth\api_key.go` (context enrichment)

**Changes:**

1. **Updated design decision comment** in `router.go` lines 109-114:
   - The SPA is intentionally served without auth middleware because the login overlay must load from the SPA itself
   - All `/admin/api/*` routes are protected by auth middleware (confirmed: lines 84-86)
   - The SPA uses `GET /admin/api/me` to verify auth state on load

2. **Added `GET /admin/api/me` endpoint** — returns authenticated key info or 401
   - Route added in `router.go` line 88: `r.Get("/me", handleAdminMe(app))`
   - Handler `handleAdminMe` in `admin_handlers.go` extracts key info from request context

3. **Enhanced auth middleware** in `api_key.go`:
   - Added `contextKey` type and `ContextKeyKeyInfo` constant
   - Middleware now stores authenticated `*APIKeyInfo` in request context
   - Added `lookup()` method (returns `*APIKeyInfo` instead of bool)
   - Added `GetKeyInfoFromContext()` helper function for downstream handlers

**Verification:**
- `/admin/api/*` routes all have auth middleware applied before reaching handlers
- The SPA can call `/admin/api/me` on load to check auth status
- If unauthenticated, the SPA shows the login overlay (client-side behavior unchanged)

### H6 — Hardcoded WEBUI_SECRET_KEY in docker-compose.yml (🔴 → ✅ CLOSED)

**File modified:**
- `C:\Projects\ollama-stack\docker-compose.yml` (line 94)

**Before:**
```yaml
- WEBUI_SECRET_KEY=${WEBUI_SECRET_KEY:-mothr_project_secure_key_2026_rtx3070}
```

**After:**
```yaml
# REQUIRED: Set WEBUI_SECRET_KEY in .env to a long random string for JWT signing.
# Example: openssl rand -hex 32
- WEBUI_SECRET_KEY=${WEBUI_SECRET_KEY}
```

**Remediation:**
- Removed the hardcoded default value `mothr_project_secure_key_2026_rtx3070`
- Added comment instructing operators to set `WEBUI_SECRET_KEY` in `.env`
- If not set, Open WebUI will fail to initialize JWT — preventing accidental use of a well-known key
